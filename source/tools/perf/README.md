# 引擎提速（给 TD 的建议，2026-10-09）

剖析（`node --cpu-prof`，固定 4 层、8 个局面 117 万节点，每节点 29 微秒）：
- `attempt`（走一步）含下层 56%；其中 `checkers`（长将记录：哪些子在将军）含下层 19%——它对一方**每一枚子**都生成一遍走法，看能不能打到对方的帅，
  可绝大多数时候对方帅根本没被将军。
- 复制局面（`cloneState` 里每枚子 `{...p}`）约 18%，加回收内存约 5%；`moveTargets` 约 20%；`inCheck` 约 12%。

## 建议 1（结果完全相同）：`rules.js` 的 `checkers` 先用 `inCheck` 看一眼
```js
function checkers(b, s) {
  const k = findKing(b, other(s)); if (!k) return [];
  if (!inCheck(b, other(s))) return [];   // 新加：对方帅没被将军，就没有子在将军
  ...（原样）
}
```
- 核对：`node tools/perf/checkers_eq.js`——400 局随机对局（含随机升级、技能、兵法）112852 个局面×方，两者 **0 次不一致**；
  另外在搜索里每次调用都拿原版核对过，也一致。
- 实测：`node tools/perf/checkers_speed.js orig` / `fast`——8 个局面分数、节点数逐个相同，耗时 32.0 → 25.3 秒（**快约 21%**，两次各跑两遍）。
- 网页里电脑按时间收手：同样时间多搜约 1/4 的节点；霸王能更常算满 4 层。

## 试过、不建议的：`inCheck` 按棋盘缓存
同一棋盘同一方重复调用约占一半，但引擎有地方算完 `inCheck` 以后还会改同一个棋盘（一个局面节点数 96638 → 96643），缓存会出错；而且不更快。
