## 3. 必须改的两处（都只涉及“按时间收手”，节点模式结果不变或可核对）

### 3.1 霸王档一步最长 9 秒（旧版最长 3.9 秒）—— **必须改**
**【实测】**10 个局面（dev 引擎；线上引擎的 5 个局面结论相同）：

| 霸王档，时间模式 budget=3000 | 线上 25eb911 | 候选 b18c278 |
|---|---|---|
| 本机（4 核、负载 13，墙钟偏悲观）平均 / 中位 / P90 / 最大 | 2.2 / 2.4 / 3.4 / **3.4 秒** | 4.3 / 4.0 / 9.0 / **9.0 秒** |
| 把时钟调快 3 倍模拟“慢 3 倍的手机” | 1.6 / 1.5 / 2.7 / **2.7 秒** | 7.3 / **9.0** / 9.0 / **9.0 秒**（一半以上的局面顶到 9 秒上限） |
| 主线程兜底（Worker 起不来，预算 1400，慢 3 倍） | 1.3 / 1.3 / 1.9 / 1.9 秒 | 4.0 / 4.2 / 5.3 / **5.3 秒**（上限本该是 4.2 秒，超出的 1.1 秒是 §3.2 那些不受时限的枚举） |
| 算到几层 | 4～5 层 | 3～4 层 |

- 原因：§2.5 的 `minNodes`。新版每节点更贵（§4.4），6 万节点在慢设备上要好几秒，于是“最多拖到 3 倍”经常被用满。
- 它还让网页里的霸王**更浅**（3～4 层）而不是更深——因为单节点贵了 60%，同样 3 秒搜到的节点更少。
- **建议改法**（任选，都不影响节点模式）：`minNodes` 降到 2 万，或把拖延上限从 `budget × 3` 改成 `× 1.5`，并让 352 行的层内截断在超过上限时无条件生效。改完**不用重跑对打**（`byNodes` 分支不读这些），只需核对节点模式着法不变（考卷 60000 节点仍 111/111 + 20 个局面着法逐一相同）。

### 3.2 校尉档汉方“提防破釜”的枚举没有时限，最坏一步 4.6 秒 CPU（旧版同一局面 0.13 秒）—— **必须改**
**【实测】**48 个局面（旧电脑自对弈产生），其中汉方走、楚方破釜还在手里的 29 个：
- `pofuPairs` 平均占这一步总 CPU 的 **40%**，平均每次思考调用 40 次。
- 最坏局面（种子 21 第 16 步）：249 次调用、枚举 79,426 个两步组合，**3.27 秒花在 pofuPairs，整步 4.77 秒 CPU，51,346 节点**。旧版同一局面：**0.13 秒、6,896 节点**（新版 35 倍）。另两个局面 1.1 秒对 0.12 秒、1.9 秒对 0.34 秒。
- 29 个局面里 3 个超过 1 秒 CPU；这是本机服务器的 CPU 时间，手机上按 2～3 倍算【推断】就是 10 秒上下。校尉是默认档，而且前三层**没有任何时间兜底**（旧版也没有，但旧版单步从没超过 0.8 秒）。
- 触发条件：电脑执汉、楚方还没用破釜（每局前 15～25 回合）。用户执楚和电脑下，或者看人机对战时，就会碰到。
- **建议改法**：
  1. 最省（节点模式着法不变）：`pfCache` 改按局面内容（棋盘 + 军功 + 轮次）做键，让 171 行的升级变体跨层命中；在 `ab` 里 `pofuPairs` 返回后补一次 `now() > deadline` 检查（霸王档有效，校尉三层无 deadline 时仍无效）。
  2. 真正管用（会改变着法，**需要重新对 25eb911 过闸**）：只对深度 ≥ 2 的分支、或只对排序前 N 的根着法做 `pfPly`；升级变体不再算破釜；或给校尉第 3 层加一个时间兜底（超时就用第 2 层的结果）。
  这一条由 chat 定方案；我只负责说清：**不改，用户执楚时校尉会偶尔“想”十秒**。

## 4. 时间模式（网页实际）与节点模式（测试）的对照数据

测试环境：本机 4 核、负载 13（三倍过载）；**CPU 时间**不受排队影响，**墙钟**偏悲观约 2～3 倍；“慢 3 倍”是把 `performance.now` 调快 3 倍的模拟。脚本和原始输出在 `scratchpad/fable/c_timing.js`、`c_timing_dev.txt`、`c_timing_live.txt`、`c_pofu_cost.js`、`c_pofu_cost.txt`、`c_worst.js`。

### 4.1 校尉档（40 个局面，三层必算完，结果确定）【实测】
| | 线上 25eb911 | 候选 b18c278 |
|---|---|---|
| 节点 平均 / P90 / 最大 | 10,774 / 24,171 / 40,293 | 18,528 / 37,012 / 47,829（×1.7） |
| CPU 毫秒 平均 / P90 / 最大 | 198 / 385 / 744 | 399 / 853 / 2,048（×2） |

### 4.2 霸王档 —— 见 §3.1 表。网页里的霸王比节点模式**浅**（3～4 层 vs 20 万节点的 4～5 层），考卷霸王 37/37 是 20 万节点下的成绩，不等于手机上的霸王。【实测 + 推断】

### 4.3 主线程兜底 —— 新版能让出主线程（`breathe()` 每 12 ms 一次，实测每步让出 14～103 次），**不会卡画面**；只是等得久（§3.1）。【实测】

### 4.4 每节点成本【实测】
- 校尉节点模式 60000、16 个局面：旧 50,691 节点/秒，新 31,213 节点/秒 → **新版每个“节点”贵 62%**（含不计入节点的 pofuPairs、升级枚举、三遍估值）。
- 霸王节点模式 20 万、10 个局面（两边都有）：旧 62,560，新 54,034 节点/秒（贵 16%）。
- 含义：总闸给两版同样的 6 万节点，是在给新版**更多的时间**；网页里按时间算，新版拿到的节点更少。这不推翻“更强”的结论（节点模式本就是约定的公平口径），但说明**时间模式下的强弱没人测过**。
