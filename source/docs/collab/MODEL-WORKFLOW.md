## 3. 模型文件的接口约定

一个模型 = 一个文件，暴露一个全局对象，入口是 `make(side, opt)`。只要这个入口的约定不变，里面怎么重做拓扑、贴图、骨架都行，TD 那边不用跟着改。

```js
const TigerHD = (() => {
  …
  return { make };          // 别的导出随意
})();

const m = TigerHD.make('r', { gold: false });
```

**`make(side, opt)` 返回的对象必须有：**

| 字段 | 说明 |
|---|---|
| `group` | `THREE.Group`。**头朝 +X，脚底在 y = 0，原点在身体正下方的地面上**。不要自己缩放，缩放由小队设（虎骑现在是 0.27） |
| `update(dt)` | 每帧调用一次，按下面的状态量摆姿势 |
| `speed` | 0 = 站着；0.8 = 行军；1.4 = 冲刺。走动的步幅、步频跟着它 |
| `pounceK` | 0→1：扑击（前身扬起、前肢前探）。腾空的那段弧线由小队抬 `group`，模型只管姿势 |
| `roarK` | 0→1：咆哮（昂首、张口） |
| `dead` | 0→1：倒地。`deadSide` = ±1 是往哪一侧倒 |

**`opt`：**`gold: true` 是技能模式四级的金色换装。画质档从 `Core.quality` 读（`'high'` / `'mid'` / `'low'`）。

**小队是怎么驱动这些量的**（做动作时照这个节奏设计）：

- 行军：`speed = 0.8`，走完归 0。
- 吃子（虎扑）：`roarK` 0→1（0.35 秒）→ 停 0.6 秒 → `speed = 1.4` 窜出一段 → `speed = 0`，0.3 秒内 `pounceK` 0→1、`roarK` 保持张口，同时小队把 `group` 沿一条弧线送到目标身前 → 落地，0.35 秒内 `pounceK`、`roarK` 回 0。
- 被吃：`roarK` 0→1（0.25 秒）→ `dead` 0→1（0.8 秒）。
- 被攻击时：`roarK` 到 0.8。
- 技能模式三级起，两侧各站一名弩手（TD 那边的事，美术不用管）；发动「齐射」时虎不动，`roarK` 到 0.5。

想要这几个量表达不了的动作（比如摆尾甩头的待机小动作、单独的受击反应），可以在返回对象上加方法或状态量，写进交付单，TD 来接触发点。

## 4. 这个代码库里会踩的坑

这些都是接虎骑时真撞上的，新模型照着避开：

1. **每走一步都会新建、销毁一次模型。**小队是临时的，演出完就 `disposeTree`。所以：
   - 原型只造一次（放样、画贴图都在这一步），之后每次 `make` 克隆一份——参照 `tiger.js` 里的 `proto()` 和 `cloneTree()`。
   - 共用的几何体要标 `geometry.userData.keep = true`，否则第一只模型销毁时会把几何体一起释放。
2. **不要用 `Object3D.clone(true)`。**描边网格（`inked` / `inkedMerged` 造出来的）在 `userData` 里挂着网格本身，自带的克隆会把它整个序列化，一次半秒到十几秒。用 `tiger.js` 里的 `cloneTree()`。
3. **带贴图的材质一律 `toon(0xffffff, { map, unique: true })`。**不带 `unique` 会被拿去算缓存键，等于把整张贴图编码一遍。
4. **随机数要可复现。**造原型前把种子复位（`tiger.js` 里是 `seed = 11`），否则每次打开花纹都不一样。
5. **写法和 `models.js` 保持一致**：基本体 / 放样 + 顶点色或画布贴图 + 水墨描边，用 `Models.P / G / inkedMerged / SIDE / C / vcMat` 和 `Core.toon / inked / canvasTex / merge / rnd`。不引外部模型文件、不引新的库、不联网取素材。
6. 顶点色落在“金色”范围里的面会被自动画成金属（见 `models.js` 开头的 `vcMat`），金饰直接给金色顶点色就行。

## 5. 性能预算

用 `python3 tools/modelshot.py` 和 `… mid` 各跑一次，看 `stats.json`。

| 项 | 高画质 | 中画质 | 现在的虎骑 |
|---|---|---|---|
| 三角面（**含描边**，描边会翻倍） | ≤ 65,000 | ≤ 40,000 | 63,294 / 37,758 |
| 首次构建（造原型） | ≤ 300 毫秒 | ≤ 300 毫秒 | 约 200 |
| 之后每次克隆 | ≤ 5 毫秒 | ≤ 5 毫秒 | 1 |
| 网格数 | ≤ 70 | ≤ 70 | 64 |
| 画布贴图 | 最大 1024，总数 ≤ 10 张 | 同左 | 9 张 |

- 参照：模型模式下整盘约 72 万三角面，现有战车一辆约 6 千。棋盘上有两个相。
- 定稿模型原样是 8 万面（加描边 16 万），放不起。现在的做法是分段数乘一个画质系数（高 0.6、中 0.42），球、锥、柱、环也一起降——见 `tiger.js` 里的 `LQ`、`seg()`、`SphG / ConG / CylG / TorG`。重做拓扑时请直接按上表的预算做，或者保留这套按系数降的机制。
- 低画质档（`Core.quality === 'low'`）现在不用精修模型，退回 `models.js` 里的简版 `makeTigerRider`。如果美术愿意给一个 ≤ 12,000 面的低模，就在 `make` 里按画质分支，并在交付单里说一声。
- `update(dt)` 里不要每帧 `new` 对象、不要每帧改几何体顶点（旗帜那种顶点动画除外，要做先在交付单里商量）。
