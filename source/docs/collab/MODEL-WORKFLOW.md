## 3. 模型文件的接口约定

一个模型 = 一个文件，暴露一个全局对象，入口是 `make(side, opt)`。只要这个入口的约定不变，里面怎么重做拓扑、贴图、骨架都行，TD 那边不用跟着改。

```js
const TigerHD = (() => {
  …
  return { make };          // 别的导出随意
})();

const m = TigerHD.make('r', { gold: false });
```

**`make(side, opt)` 返回的对象必须有：**

| 字段 | 说明 |
|---|---|
| `group` | `THREE.Group`。**头朝 +X，脚底在 y = 0，原点在身体正下方的地面上**。不要自己缩放，缩放由小队设（`model-lab` 上精修虎骑是 0.27，`dev` 上的简版是 0.26） |
| `update(dt)` | 每帧调用一次，按下面的状态量摆姿势 |
| `speed` | 0 = 站着；0.8 = 行军；1.4 = 冲刺。走动的步幅、步频跟着它 |
| `pounceK` | 0→1：扑击（前身扬起、前肢前探）。腾空的那段弧线由小队抬 `group`，模型只管姿势 |
| `roarK` | 0→1：咆哮（昂首、张口） |
| `dead` | 0→1：倒地。`deadSide` = ±1 是往哪一侧倒 |

**`opt`：**`gold: true` 是技能模式四级的金色换装。画质档从 `Core.quality` 读（`'high'` / `'mid'` / `'low'`）。

**小队是怎么驱动这些量的**（做动作时照这个节奏设计）：

- 行军：`speed = 0.8`，走完归 0。
- 吃子（虎扑）：`roarK` 0→1（0.35 秒）→ 停 0.6 秒 → `speed = 1.4` 窜出一段 → `speed = 0`，0.3 秒内 `pounceK` 0→1、`roarK` 保持张口，同时小队把 `group` 沿一条弧线送到目标身前 → 落地，0.35 秒内 `pounceK`、`roarK` 回 0。
- 被吃：`roarK` 0→1（0.25 秒）→ `dead` 0→1（0.8 秒）。
- 被攻击时：`roarK` 到 0.8。
- 技能模式三级起，两侧各站一名弩手（TD 那边的事，美术不用管）；发动「齐射」时虎不动，`roarK` 到 0.5。

想要这几个量表达不了的动作（比如摆尾甩头的待机小动作、单独的受击反应），可以在返回对象上加方法或状态量，写进交付单，TD 来接触发点。

## 4. 这个代码库里会踩的坑

这些都是接虎骑时真撞上的，新模型照着避开：

1. **每走一步都会新建、销毁一次模型。**小队是临时的，演出完就 `disposeTree`。所以：
   - 原型只造一次（放样、画贴图都在这一步），之后每次 `make` 克隆一份——参照 `tiger.js` 里的 `proto()` 和 `cloneTree()`。
   - 共用的几何体要标 `geometry.userData.keep = true`，否则第一只模型销毁时会把几何体一起释放。
2. **不要用 `Object3D.clone(true)`。**描边网格（`inked` / `inkedMerged` 造出来的）在 `userData` 里挂着网格本身，自带的克隆会把它整个序列化，一次半秒到十几秒。用 `tiger.js` 里的 `cloneTree()`。
3. **带贴图的材质一律 `toon(0xffffff, { map, unique: true })`。**不带 `unique` 会被拿去算缓存键，等于把整张贴图编码一遍。
4. **随机数要可复现。**造原型前把种子复位（`tiger.js` 里是 `seed = 11`），否则每次打开花纹都不一样。
5. **写法和 `models.js` 保持一致**：基本体 / 放样 + 顶点色或画布贴图 + 水墨描边，用 `Models.P / G / inkedMerged / SIDE / C / vcMat` 和 `Core.toon / inked / canvasTex / merge / rnd`。不引外部模型文件、不引新的库、不联网取素材。
6. 顶点色落在“金色”范围里的面会被自动画成金属（见 `models.js` 开头的 `vcMat`），金饰直接给金色顶点色就行。

## 5. 性能预算

用 `python3 tools/modelshot.py` 和 `… mid` 各跑一次，看 `stats.json`。

| 项 | 高画质 | 中画质 | 现在的虎骑（M2） |
|---|---|---|---|
| 三角面（**含描边**，描边会翻倍） | ≤ 65,000 | ≤ 40,000 | 7,812（四级金装 10,056）；低画质 4,248 |
| 首次构建（造原型） | ≤ 300 毫秒 | ≤ 300 毫秒 | 约 60～130 |
| 之后每次克隆 | ≤ 5 毫秒 | ≤ 5 毫秒 | 1～3 |
| 网格数 | ≤ 70 | ≤ 70 | 64（金装 68） |
| 画布贴图 | 最大 1024，总数 ≤ 10 张 | 同左 | 9 张（金装 10 张） |

- 参照：模型模式下整盘约 72 万三角面，现有战车一辆约 6 千。棋盘上有两个相。
- 虎骑现在按面数档直接生成（`tiger.js` 的 `LOD` / `QLOD = { high: 2, mid: 2, low: 4 }`）：高、中画质是 Ham 定的对局档（不含描边 4,002 面），低画质 1,998 面。预算上限仍是上表那几个数，新模型不必做到这么省，但别超。
- `update(dt)` 里不要每帧 `new` 对象、不要每帧改几何体顶点（旗帜那种顶点动画除外，要做先在交付单里商量）。

## 6. 交付：先出图给 Ham，他点头之后再交

顺序是 **出图 → Ham 点头 → 推送交付**，不是先推上来再等人看。

1. 做好之后，先在自己这边跑 `modelshot.py`（高、中各一次），把图**直接发给 Ham**：近景、和车马象并排、棋盘视角，动了动作的再加动作抽帧。这一步不经过 TD。
2. Ham 说要改就接着改，改完再出图，直到他点头。
3. **Ham 点头之后**才交付：
   - 在 `model-lab` 上提交、推送。

   - 在 `source/docs/collab/model-to-main.md` **最上面**加一条交付单，编号接着往下排（M1、M2…）：

```
## M3 · 10-06 · 交付
```

## 8. 界面（UI）改版

Ham 让美术重新设计界面。界面和模型不一样：页面结构、样式都在 `source/src/template.html`，按钮和提示的文字、行为在 `main.js`，这两个文件 TD 几乎每天在改。所以另立几条：

1. **先出设计图给 Ham**（效果图 / 改版前后对比），他点头之后再动手改代码——和模型一样的顺序。
2. **美术可以改的**：`template.html` 里的样式（`<style>`）和页面结构；需要的图片、字体素材。分支还是 `model-lab`。
3. **不要改的**：`main.js` 和别的脚本。要改行为（按钮点了干什么、什么时候显示）写进交付单，TD 来改。
4. **不要动元素的 `id` 和 `data-*` 属性**（脚本靠它们找元素）；要删、要改名的，在交付单里逐个列出来。`class` 可以加，已有的 `class` 改名同样要列。
5. **开工前、交付前各合一次 `origin/dev`**（`git fetch origin && git merge origin/dev`），`template.html` 有冲突自己解掉——TD 这边随时可能加一段说明或一个按钮。交付前 `node build.js` 能过、`node test/*.test.js` 不受影响。
6. **每个界面都要看到**：大厅（建房 / 加入 / 人机 / 本地）、对局中（电脑宽屏、手机竖屏 360 宽）、技能栏和兵法按钮、选子 / 确认 / 设置 / 玩法说明 / 更新说明这些弹窗、暂停、终局卡片、观战。交付单里写明哪些看过、哪些没动。
7. 交付单格式同第 6 节，标题写「界面」。TD 收到后合进 `dev`，把所有界面在电脑和手机宽度各过一遍，再请 Ham 点头上线。

## 9. 已经定下来的事（不用再问 Ham）

- 汉方「相」的形象从谋士车驾改成「文臣虎骑」：白虎驮着一位宽袍文臣。只改视觉，走法、规则、数值不动，棋子名仍叫「相」。楚方的象不动。
- 造型是「持节潜行」（朱袍、节杖、虎压低身子潜行），现在的版本是美术的 M2：后腿三段、四肢外撑、带鞍座；四级是虎披金甲、宝座式鞍、金节杖，文臣衣冠不变。
- 攻击的是虎，文臣不近战：咆哮、扑击时节杖保持不动（Ham 10-05 定）。技能模式三、四级有两名弩手随护，但**平时不在场**，只在行进和攻击时出列；三、四级的普通攻击是组合——弩手先放一轮箭，虎再扑出去。「齐射」是弩手放两轮箭，虎不动。四级换金装。
- 从正常对局视角看，汉相、汉车、汉马、楚象的剪影要一眼能分清。
- 相的台词已改：移动「白虎开道」「谋定而后动」，吃子「犯汉者，虎噬之！」「放虎！」。称号也定了（Ham 交给 TD 定）：汉军相 → 驭虎长史 → 持节护军 → 白虎相国。
