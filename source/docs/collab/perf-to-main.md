## P2（10-10）对局静止时省电降到每秒 15 帧

**拍板**：Ham 10-10 12:27 在优化部审批台 perf-001 选「乙1 每秒 15 帧」。美术总监同意，意见见下面第 3 条。

**改什么**：`src/core.js` 主循环一处，补丁 `perf/P2-eco-15fps.patch`。只在省电开着（手机默认）、而且“静止”的时候生效。静止的意思是：最近 1.5 秒没碰屏，没有演出，镜头不动。
1. 静止时最短帧间隔 31 → 64 毫秒，也就是 30 帧 → 15 帧。一碰屏、走子、演出、结算都照旧满帧。
2. 一帧最多推进的时间：省电时 0.05 → 0.1 秒。不放宽的话，15 帧时每帧 0.067 秒会被截短，背景动画会慢下来。不开省电的照旧是 0.05 秒。
3. 静止时故意少画的帧，不算进帧时间统计。否则 `main.js` 的“自动降画质”（平均每帧超过 40 毫秒就降）会在静止 10 秒后把画质误降到“低”。

**改前 → 改后**（手机 390×844、画质中、CPU 降速 4 倍，只计数不真画，最新 `main` 打包）：
| 项 | 改前 | 改后 |
|---|---|---|
| 对局静止、省电开：每秒画几帧 | 30 | **15** |
| 同上：主线程占用 | 37% | **24%** |
| 同上：脚本占用 | 22% | **11%** |
| 同上：记进自动降画质的帧（每 5 秒） | 108 帧，平均 33.5 毫秒 | 0 帧（静止不计） |
| 静止中途碰屏 | — | 立刻恢复满帧 |
| 动画时间 / 真实时间 | 1.50 | 1.50（不变慢；1.5 是游戏速度设定） |
| 省电关（电脑） | 56 帧 | 56 帧（不受影响） |

**测试**：`rules engine jieqi bingfa beishui r6 bfai bfai.policy` 全过。P1、P2 两个补丁各自，以及先 P1 后 P2，在最新 `main` / `dev`（54ba8bc）上 `git apply --check` 都干净。

**建议（不在补丁里，TD 定）**：`?perf` 面板的“帧/秒”数的是浏览器的刷新次数，不是真正画了几帧，所以省电时还显示 60。Ham 用它看真机数字时会误判。可以改成显示 `Core.takeFrames` 或者真画的次数。

**上线说明（NEWS 草稿）**：手机上对局停着不动时更省电、更凉（优化部）。

## P1（10-10）棋盘装饰合并：每帧少约 90 次绘制，画面不变

**拍板**：Ham 10-10 12:02 在优化部拍板单 p-03 选「丙 一起做」（甲 = 本单，不改画面，直接做）。

**改什么**：`src/board.js` 一处，补丁 `perf/P1-board-bake.patch`（47 行）。
- 两半棋盘（`makeHalf`）造好以后过一遍 `bakeStatic`：同一材质、同样影子设置的静止网格合成一个网格；描边材质按“粗细 + 颜色”算同一种。
- 不动的：半透明的、多材质的（漆盒）、带贴图的（棋盘面，`boardTops` / `polishBoard` 照旧）、棋子、走法提示等动态的东西。
- 合完把空的外层组拿掉。

**改前 → 改后**（同一台机器，手机 390×844、画质中、开局静止画面）：
| 项 | 改前 | 改后 |
|---|---|---|
| 两半棋盘的网格数 | 62 + 62 | 14 + 14 |
| 每帧绘制次数（手机默认镜头） | 350 | **260（−26%）** |
| 每帧绘制次数（电脑斜视角，看得到木梯、包角） | 426 | **335（−21%）** |
| 每帧三角形 | 29.5 万 | 29.5 万（不变） |
| 显卡上的几何体数 | 159 | 107 |
| 每帧发绘制命令的 CPU 时间（中位数，本机不降速，两次） | 3.1 / 2.8 毫秒 | 2.4 / 2.6 毫秒（约 −15%） |

**帧率**：这里只有软件渲染（真画一帧约 200 毫秒，帧率被它卡住），帧率量不准，所以没写帧率，改报上面的“绘制次数”和“发命令的 CPU 时间”。手机上省的是显卡每帧少处理约 90 次绘制，要靠真机 `?perf` 面板看。

**截图**（同一机位、定住时间，左 / 上改前，右 / 下改后）：`perf/P1-phone.jpg`（手机 390×844）、`perf/P1-pc.jpg`（电脑 1280×720 斜视角，看得到木梯、铜包角）。格线红光的位置不一样，是两次截图时动画走到的时刻不同，和补丁无关。

**测试**：`rules engine jieqi bingfa beishui r6 bfai bfai.policy` 全过。
`git apply --check` 在最新 `main`（54ba8bc）和 `dev`（f6edb95）上都能干净打上；上表的 CPU 时间是在最新 `main` 上打补丁量的（346 → 258 次）。在 `dev` 上打补丁后打包、开局：每帧 345 → 257 次，没有报错。
